    Calibration workflows

    A calibration workflow is an ordered set of steps (calibrations, and the analyses around them) whose results are merged into one target model; see Calibration workflows for the how-to. WorkflowBuilder makes a workflow with API calls and runs it; the functions below it run, plan and read a workflow file however it was written.

    Building a workflow

    libcuflynx.calibration_workflow.builder.WorkflowBuilder 

    WorkflowBuilder(
    name,
    target,
    *,
    directory,
    description=None,
    module_library_dirs=(),
    settings=None
)

    A calibration workflow made by API calls, written as an ordinary calibration_workflow.json and run from Python.

    Creating a builder writes nothing: files are written by :meth:write (which :meth:run, :meth:plan, :meth:status, :meth:model and :meth:plot_step call).

    Parameters:

    Name Type Description Default
    name

    the workflow's name (workflow_name). It names the functions files and the run's default output directory.

    		 required
    target

    the model the calibrated values are merged into, and the model of each step that names none: a module array path, :func:module_array, :func:library_module, :func:external_model or :func:cellml_model.

    		 required
    directory

    where the workflow file, its data/ and its functions files are written; created by :meth:write. Relative paths given to the builder are relative to the working directory at the time of the call.

    		 required
    description

    the workflow's description.

    		 None
    module_library_dirs

    the module libraries (directories) the models' modules come from. Needed whenever a model names a library module, a module array's too.

    		 ()
    settings

    the workflow's settings, user_inputs.yaml keys (spec.ALLOWED_SETTINGS: param_id_method, optimiser_options, dt, ...), checked at once. A step's own settings are merged over them.

    		 None

    Raises:

    Type Description
    WorkflowError

    an unknown setting, or a name or target the schema refuses.

    Attributes:

    Name Type Description
    directory Path

    the absolute directory the workflow is written to.
    path Path

    the workflow file, <directory>/calibration_workflow.json.
    settings dict

    the workflow's settings, paths absolute. Change them with :meth:update_settings, which checks them.

    directory property 

    directory

    The absolute directory the workflow is written to (a pathlib.Path).

    path property 

    path

    The workflow file (a pathlib.Path).

    name property 

    name

    The workflow's name (workflow_name).

    target property 

    target

    The target model, as given (a copy; paths absolute).

    module_library_dirs property 

    module_library_dirs

    The module libraries the models come from (absolute paths).

    output_dir property 

    output_dir

    Where :meth:run writes unless told otherwise: <directory>/workflow_output/<name> (a pathlib.Path), which is also where the cuflynx-calibration-workflow command runs the written file.

    steps property 

    steps

    The step ids (a list), in the order they were added.

    load(path)

    A builder for an existing workflow, written back to the same file.

    Parameters:

    Name Type Description Default
    path

    the workflow file, or the directory holding its calibration_workflow.json.

    		 required

    The functions files a builder wrote beside it are read back (their functions and imports), so functions can be added, replaced or removed. Returns the builder.

    update_settings 

    update_settings(**settings)

    Set workflow settings (the keys of spec.ALLOWED_SETTINGS), checked against the schema at once. A dict setting is merged one level deep, as a step's are: update_settings(optimiser_options={'seed': 2}) keeps the other optimiser options. A setting given as None is removed. Nothing is written until :meth:write.

    Type Description

    add_calibration 

    add_calibration(
    id,
    *,
    obs_data,
    params_for_id=None,
    params_for_id_from=None,
    model=None,
    fixed_from=(),
    priors_from=(),
    store_distribution=False,
    start_from=None,
    emulator_from=None,
    emulator_dir=None,
    module=None,
    submodule=None,
    module_map=None,
    settings=None,
    description=None,
    comment=None

    Add a calibration: fit parameters of a model to an obs_data.

    Nothing is written or run by this call; the step is checked against the schema, and the dicts given are copied. A step with this id already is replaced in place, so to change a step, change what you pass and call this again.

    Parameters:

    Name Type Description Default
    id

    the step's name: other steps refer to it and its results go to <output_dir>/<id>/. No / or \; at most 80 characters; unlike every other id whatever the case.

    		 required
    obs_data

    what to fit: a path to an obs_data JSON file, an obs_data dict, or an ObsDataCreator. A dict is written to data/<id>_obs_data.json by :meth:write.

    		 required
    params_for_id

    what to calibrate: a path to a params_for_id JSON file, a list of {vessel_name, param_name, min, max} entries (as CVS0DParamID takes), a list of {targets, min, max} entries, or a {"version", "params"} document. Not a path: written to data/<id>_params_for_id.json.

    		 None
    params_for_id_from

    instead of params_for_id, the reduction step (:meth:add_reduction) whose chosen parameters are calibrated.

    		 None
    model

    the model the step runs on: a module array path, :func:module_array, :func:library_module or :func:selection. Default: the target.

    		 None
    fixed_from

    calibration or set step ids, or :func:fixed entries for only some of a step's values (one, or a list), whose values are fixed in this step's model; this step runs after them.

    		 ()
    priors_from

    step ids or :func:prior entries whose stored distributions become this step's priors (those steps set store_distribution).

    		 ()
    store_distribution

    after the fit, sample the posterior by MCMC (needs the UQ_options setting) and store it for later steps.

    		 False
    start_from

    a calibration or set step at whose values this step's own parameters start.

    		 None
    emulator_from

    an emulation step (:meth:add_emulation) whose emulator this step is evaluated on; give the same model, obs_data and params_for_id. With params_for_id_from a reduction of that emulator's params_for_id, the step calibrates the parameters the reduction kept and holds the emulator's others at their values in the emulation step's model.

    		 None
    emulator_dir

    instead of emulator_from, the directory of an emulator trained outside the workflow.

    		 None
    module

    for a library module in a module-array target, the module it is (inferred when the module occurs once).

    		 None
    submodule

    for a library module in a library supermodule target, where it sits (inferred when the module occurs once).

    		 None
    module_map

    for a module-array model, {its module name: the target's}.

    		 None
    settings

    this step's settings, merged over the workflow's one dict level deep.

    		 None
    description

    free text, shown in reports.

    		 None
    comment

    free text, kept in the file.

    		 None

    Returns:

    Type Description

    id.

    Raises:

    Type Description
    WorkflowError

    the step does not fit the schema (the message names the key).

    add_reduction 

    add_reduction(
    id,
    *,
    sensitivity_from=None,
    param_reduction_options=None,
    params_for_id=None,
    method=None,
    n_params=None,
    parameters=None,
    reason=None,
    index_type=None,
    criterion=None,
    threshold=None,
    min_mode_std=None,
    variance_fraction=None,
    min_index=None,
    redundancy_check=None,
    redundancy_statistic=None,
    redundancy_converged_only=None,
    redundancy_convergence_tol=None,
    description=None,
    comment=None
)

    Add a reduction: choose the parameters a later step calibrates (its params_for_id_from) from the Sobol indices of a sensitivity step, or by hand (method='manual').

    Parameters:

    Name Type Description Default
    id

    the step's name (see :meth:add_calibration).

    		 required
    sensitivity_from

    the sensitivity step whose results are reduced (not for 'manual').

    		 None
    param_reduction_options

    the reduction's options (the schema's param_reduction_options), written as the step's settings.param_reduction_options; a key left out takes the schema's default, and method is 'pca' unless given:

    • method: 'pca' (one parameter per informative mode of the Sobol outputs), 'sobol' (the n_params parameters with the highest index) or 'manual' (the parameters named, chosen by hand);
    • parameters: manual: the parameters to keep, each named as its params_for_id entry is labelled ('heart/E_lv_A');
    • reason: manual: why these parameters were chosen;
    • n_params: how many parameters to keep (pca: at most; sobol: required);
    • index_type: 'ST' (total, the default) or 'S1' (first-order);
    • criterion: sobol: a parameter's score, the 'max' or 'mean' of its index;
    • threshold: sobol: drop parameters scoring below this;
    • min_mode_std: pca: a mode is informative when its std over the samples is at least this many obs_data stds (default 1);
    • variance_fraction: pca: only the leading modes explaining this fraction of the variance (default 1, no cut);
    • min_index: pca: skip a mode whose largest index is below this (default 0.05);
    • redundancy_check: the check for parameters with the same effect on the outputs;
    • redundancy_statistic: pca with redundancy_check: 'median' (default) or 'rms' of a parameter's unexplained effect over the local Jacobian points;
    • redundancy_converged_only: pca with redundancy_check: leave out the points whose derivatives change with the step (needs sa_options.jacobian_check_steps);
    • redundancy_convergence_tol: the largest relative change between the two steps (default 0.1).
    		 None
    params_for_id

    manual: the params_for_id whose entries, with their ranges, are kept (what :meth:add_calibration takes).

    		 None
    description, comment

    free text.

    		 required

    Returns id.

    Raises:

    Type Description
    WorkflowError

    an option is given both ways with different values, or the step does not fit the schema.

    add_operation 

    add_operation(*funcs, overwrite=False)

    Add functions an obs_data item can name as its operation.

    Each function's source is copied (now) and written by :meth:write into <name>_operation_funcs.py beside the workflow, which the workflow's operation_funcs_external_path setting then names, so every rank, the command line and CUFLynx load it. A function added again replaces its earlier source: edit it where it is defined and add it again.

    Parameters:

    Name Type Description Default
    *funcs

    functions defined with def at the top level of a cell or module. A helper another function calls is added too (name it with a leading _ and it is not registered as an operation).

    		 ()
    overwrite

    replace a functions file that was edited by hand, or that no builder wrote. Without it such a file is refused, so its edits are not lost.

    		 False

    Raises:

    Type Description
    WorkflowError

    a function cannot be written to a file (a lambda, a closure, a name defined only in the session), the workflow names another functions file, or the file on disk would lose hand edits.

    Raises:

    Type Description

    The functions file

    libcuflynx.utilities.user_funcs_file

    The files of user functions -- operations, cost functions, modifiers -- that the operation_funcs_external_path, cost_funcs_external_path and modifier_funcs_external_path settings name.

    One layout for every writer (CUFLynx's "Custom funcs" dialog, and calibration_workflow.WorkflowBuilder.add_operation), so either can read and rewrite what the other wrote::

    """<the kind's header docstring>"""
import numpy as np
from libcuflynx... import <the kind's decorators>
mb = make_math_backend("numpy")         (operations and cost functions)
# libcuflynx-generated sha256: <hex>     (the checksum of the rest of the file)

import scipy.signal as signal           (the imports the functions use, if any)

CUFLYNX_OPERATIONS = ["peak_count", "half_mean"]     (the functions, in order)


@series_to_constant
def half_mean(x, series_output=False):
    ...

    The decorators are imported, never defined, so libcuflynx registers only the functions below them (param_id.external_funcs.register_funcs_from_file keeps the callables whose module is the file). :func:read_funcs_file reads such a file back: its functions (each with its decorators) in order, and the imports beyond the header's.

    The checksum line is a comment, so Python and any reader of the functions ignore it. It is the sha256 of the file without that line: while it matches (:func:is_unedited), the file is exactly what a writer generated and can be generated again without losing anything. A file holds only the header, imports and functions: :func:unkept_statements lists what a rewrite would drop (constants, classes), so a writer can refuse instead.
